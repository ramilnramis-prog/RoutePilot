Plan

Opening a plan reads it through GET /api/plans/{id}. “Create / open the DEMO plan” calls POST /api/plans, which returns the same deterministic fixture every time instead of duplicating it.

Override controls (the driver decides)

Every control below changes server state through one documented endpoint and then re-reads the affected panels from the server. Nothing on this page applies a recommendation by itself: the accept control only ever sends mode=recommend with the stop the engine recommended and this page displayed (D4/D32/D39(d)).

First-stop decision

“Accept the recommendation” sends POST /api/plans/{id}/selection with {"mode": "recommend", "stop_id": <the recommended stop>} and is refused unless that stop really is the engine's current recommendation. It is disabled until a recommendation has been read.

The manual picker lists only the stops the API reports as enabled. “Use this stop” sends POST /api/plans/{id}/selection with {"mode": "manual", "stop_id": <the chosen stop>}: the choice is the driver's, its provenance is manual_choice and it is pinned (D5/D6/D7).

“Cancel the selection” sends DELETE /api/plans/{id}/selection and the plan returns to awaiting_first_stop_choice - the domain never substitutes a stop (D8/D9).

Stops: disable / restore / priority

Each stop row below offers its own edit controls. Both send PUT /api/plans/{id} with a stops list carrying exactly one change: {"stops": [{"stop_id": …, "enabled": false|true}]} to disable or restore, and {"stops": [{"stop_id": …, "priority": <the new priority>}]} to change the priority. There is deliberately no drag/reorder control (out of scope, D21/D39(d)).

Recalculate

POST /api/plans/{id}/optimize recomputes the recommendation, computes the committed route and appends exactly one immutable run row. Afterwards the route, the selection state and the run history are all re-read from the server; the measured computation_seconds of the recalculation is shown.

Map (Leaflet + OSM-compatible tiles)

The line drawn between the stops is synthetic straight-line geometry: it is the route order the engine returned, joined by straight segments. It is not road routing and carries no road distance, no turn instructions and no traffic.

First-stop recommendation (advisory)

A recommendation is advisory and NOT an applied decision. It is recomputed live for this request, it is not plan state, and it does not change the plan: the driver decides whether to accept it or choose another stop (D4/D11/D32).

Run history (read-only)

Immutable history, oldest first, from GET /api/plans/{id}/runs. A run is never edited, reordered or deleted: only POST /api/plans/{id}/optimize (the Recalculate control) appends one row. The recorded recommendation of a run is the audit of what that run showed - it is history, never the plan's current first-stop decision.

What this build does NOT do

Read from the API's own capability report (GET /api/health, not_implemented_capabilities, route_modes and timezone_data) - not from a list written in this page. An unimplemented capability is never presented as working (D16).

RoutePilot recommends, the driver decides. Synthetic demo data is never presented as real routing, traffic or opening hours (spec sections 33/34; D15/D16/D23/D32).
